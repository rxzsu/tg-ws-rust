## [1.2.1] — 2026-10-31

### Добавлено

- **`dc_redirects` задействованы**: пользовательские DC:IP теперь реально
  используются в TCP-фолбэке и в `dst=` для CF-воркеров (раньше поле
  валидировалось и показывалось в настройках, но движок его игнорировал).
  Дефолт стал пустым — без переопределения работает встроенная таблица DC;
  сохранённые конфиги со своими значениями начнут их применять.
- **Тумблеры CF-источников работают**: «Собственные домены» и
  «Cloudflare Worker» гейтят свои списки — домены, сохранённые при
  выключенном тумблере, больше не используются молча.
- **Ответ на PING апстрима**: мост теперь отвечает pong'ом на ping от CDN-фронта
  (общий writer за async-мьютексом, `WsPonger`). Раньше ping оставался без
  ответа — фронтенды рвали «тихое» соединение после ~100 с паузы, и клиент
  переподключался на каждом простое.
- **Гонка транспортов экономит хендшейки**: сокеты проигравших кандидатов,
  успевшие завершить TLS+WS до отмены, попадают в пул вместо закрытия.
- **Гейт типизации и форматирования фронтенда**: `bun check` (нативный
  тайпчекер, TS-слой — контракт `ProxyConfig`/`TelemetrySnapshot` с Rust) и
  `bun fmt` встроены в `bun run build` и CI; скрипты `check` / `fmt` /
  `fmt:check` / `tauri`; `bun install --frozen-lockfile` в CI.
- **Фронтенд: производительность и UX**: стабильные ключи строк лога
  (перерисовка 800 строк каждые 2 с → только новые строки), автоскролл
  лога только у нижнего края, поллинг логов без мигания кнопки «Обновить»
  и без наложения с ручным refresh, стабильные ссылки цветов шейдера
  (uniforms больше не пересобираются каждый тик), аллокация QR-библиотеки
  вынесена в динамический импорт, guard от двойного клика по кнопке
  питания, персист настроек UI (сайдбар, «Продвинутые»), подсветка пресета
  снимается при ручной правке полей, кламп значения в числовых полях
  (дроби/экспонента больше не доходят до serde).
- **Фронтенд: доступность и ошибки**: `lang="ru"`, `aria-live` на тостах,
  `aria-label` на переключателях, фокус-трап + `role="dialog"` +
  возврат фокуса в модалках, catch-обработчики с тостами на всех
  открываемых ссылках и копировании, ошибки загрузки конфига и теста
  связности показываются пользователю, ссылка «Сообщить о проблеме»
  ведёт куда открывает.

### Исправлено

- **Splitter, disabled-режим**: после отключения парсинга каждый следующий
  чанк возвращался вместе со всем накопленным ранее буфером — квадратичный
  дубликат трафика (буфер чистился только раз, `head` оставался нулевым).
  Теперь в passthrough-режиме буфер держит только текущий чанк.
- **Splitter, лимит длины пакета**: заявленная в заголовке длина пакета
  (до ~2 ГБ в intermediate-режиме) копилась в буферах без потолка — любой
  клиент с валидным секретом мог вызвать OOM. Пакеты больше 16 МБ
  отключают парсинг (passthrough).
- **Утечка `connections_active`**: остановка моста с живыми сессиями
  абортит задачи без декремента счётчика — телеметрия навсегда показывала
  фантомные соединения. Заменено на RAII-guard.
- **ECH-кэш сериализовал соединения**: DoH-феч выполнялся под мьютексом
  кэша (до ~24 с) — все апстрим-коннекты, включая параллельную гонку
  транспортов, стояли в очереди. Феч вынесен за пределы лока.
- **Гонка старт/стоп моста**: команды UI, трей, Android-плитка и автостарт
  выполнялись конкурентно; второй старт мог перезаписать shutdown-канал
  первого (остановка без drain). Все операции жизненного цикла сведены под
  общий лок; флаг `running` коммитится до установки канала.
- **Статус моста в UI**: бэкенд эмитит `bridge-state-changed` при каждом
  переходе (UI-кнопка, трей, Android-плитка, автостарт, самопроизвольный
  выход задачи) — Dashboard больше не показывает устаревший статус.
- **«Перезапустить прокси»** в трее и команда `restart_proxy` больше не
  стартуют остановленный мост; автостарт валидирует конфиг до поднятия
  статуса и FGS-уведомления.
- **Запись ServerHello** ограничена таймаутом: клиент с нулевым окном
  больше не держит задачу до 15-минутного idle-watchdog.
- **Accept-цикл**: burst ошибок `accept` (WSAECONNRESET при сканировании
  порта на Windows) больше не крутит busy-loop с error-логом на каждой
  итерации — backoff и debug-уровень для транзиентных ошибок.
- **Настройки: списковые поля** (CF-домены, воркеры, релеи, DC-редиректы)
  больше не «съедают» ввод: разделители и частично набранный текст больше
  не стираются при наборе (round-trip через парсер убран из v-model).
- **Таймауты фоновых коннектов пула**: replenish и warm-up подключались
  без ограничения — чёрная дыра вместо домена держала фоновую задачу до
  OS-таймаута SYN, всплеск pool-hit плодил неограниченные коннекты.
  Теперь тот же `connect_timeout`, что у клиентских путей.
- **Усечение длины WS-фрейма**: 64-битная длина приводилась к `usize`
  до проверки лимита — на 32-битных сборках огромная заявленная длина
  тихо усекалась в маленькую и парсер фреймов рассинхронизировался.

### Безопасность

- **Capabilities сужены**: `opener:default` удалён (плагин открывал из
  вебвью `http://`, `mailto:`, `tel:` в обход whitelist'а `open_url`; JS API
  плагина не используется). Из `desktop.json` убраны window-пермишены,
  дублирующие Rust-команды.
- **Alt+F4 / закрытие окна** больше не убивают процесс вместе с мостом —
  окно скрывается в трей (`CloseRequested → prevent_close + hide`).
- **Выход из трея** останавливает мост с drain-ом сессий до `app.exit(0)`;
  на `ExitRequested` (logoff, graceful kill) мост останавливается
  best-effort.
- **GitHub API**: ответы (обновления, список CF-доменов, DoH) парсятся
  полноценным мини-HTTP-клиентом — проверка статус-кода, декодирование
  chunked, кап размера тела. 403 rate-limit больше не выглядит как «обновлений нет».
- **MAC-сравнение в Fake TLS** переведено на constant-time.
- **`test_connectivity`**: не более 8 пользовательских доменов за раз —
  вебвью не может запустить тысячи параллельных TLS-хендшейков.
- **FileProvider** (Android): вместо всего external storage и кэша — только
  каталог `Pictures` приложения, куда пишутся фото для camera-intent.
- **Keystore-пароль** генерируется CSPRNG (`RandomNumberGenerator`) вместо
  `Get-Random`; на каталог ключа устанавливаются строгие ACL.
- **Android: FGS только под управлением Rust** — плитка больше не включает
  foreground service сама: rejected-старт (битый конфиг, занятый порт)
  больше не оставляет уведомление «Мост активен» при выключенном прокси.
  FGS проверяет реальное состояние моста через JNI и самогасится при
  ложном старте (restart после смерти процесса по `START_STICKY`).
- **Android: состояние плитки синхронизируется с Rust** — новый JNI-запрос
  `nativeIsRunning`: плитка перепроверяет состояние при каждом показе и
  через 1.5 с после клика (успешный старт мог провалиться на валидации).
- **Android 13+**: разрешение `POST_NOTIFICATIONS` теперь запрашивается в
  рантайме — уведомление FGS раньше всегда было скрыто.
- **Android 10+**: холодный запуск из плитки через
  `startActivityAndCollapse` вместо `startActivity` — обычный запуск
  activity из фона мог молча игнорироваться системой.
- **CI**: все экшены закреплены по SHA (включая `@latest`), у джоб объявлены
  минимальные `permissions`, добавлен Dependabot для обновления пинов.

## [1.2.0] — 2026-10-24

### Добавлено

- **ECH (Encrypted Client Hello)**: SNI в TLS-рукопожатии к апстримам
  шифруется — DPI видит только служебный домен Cloudflare, а не
  `kws*.web.telegram.org` или пользовательские домены. Конфиг ECH берётся из
  DNS HTTPS-записи через DoH (1.1.1.1 / 8.8.8.8) и кэшируется; нет поддержки
  у домена или сервер отклонил рукопожатие — автоматический откат на обычный
  TLS. Отключается тумблером «ECH» в настройках.
- **Гонка транспортов (Happy Eyeballs)**: прямые WS-подключения к топ-3
  доменам запускаются параллельно, побеждает первый успешный хендшейк —
  заблокированный фронт больше не стоит полный `connect_timeout` в
  последовательном переборе.
- **Android: плитка Quick Settings** «Прокси» — старт/стоп моста прямо из
  шторки, без открытия приложения. При холодном процессе плитка открывает
  приложение, чей автостарт поднимает мост (обратный JNI-вызов в Rust).

### Исправлено

- **Таймауты fallback-подключений**: CF Worker / пользовательские домены /
  балансер подключаются с тем же таймаутом, что и прямой путь; зависший
  хендшейк одного фолбэка больше не блокирует всю цепочку.
- **Slowloris-хендшейк**: чтение клиентского рукопожатия ограничено 15 с,
  молчащий клиент больше не держит сокет вечно; полудохлые сессии моста
  закрываются idle-таймаутом (15 мин без трафика в обе стороны).
- **Ротация логов на Windows**: дескриптор файла закрывается до `rename` —
  sharing violation больше не отключает ротацию, `proxy.log` уважает
  `log_max_mb`.
- **Гонка старт/стоп моста**: остановка ждёт фактического завершения задачи
  (JoinHandle, до 5 с) вместо `sleep(250 мс)`; быстрый рестарт больше не
  падает с «порт занят» при зелёном статусе. Shutdown-канал создаётся до
  спавна задачи — stop сразу после start гарантированно доходит.
- **`bufpool` без `unsafe`**: буферы держат `Arc<BufferPool>` вместо сырого
  указателя — дроп пула больше не даёт висячий указатель.
- **Пул соединений**: паники на poisoned-локе заменены на восстановление;
  лишний коннект при переполнении очереди закрывается явно, а не тихо течёт.
- **Balancer**: GitHub-запросы ограничены таймаутами (10 с connect/read,
  25 с общая проверка обновлений) — зависшее соединение больше не
  останавливает ежечасное обновление доменов навсегда.
- **Телеметрия**: `telemetry-update` шлётся раз в секунду только при
  работающем мосте и видимом окне (иначе 5 с / пауза) — меньше ре-рендеров
  и расхода батареи на Android; домены в `last_error` и маршрутах DC
  цензурируются так же, как в файловых логах.
- **Логи**: инкрементальный tail по байтовому смещению вместо чтения всего
  файла каждые 2 секунды; экран логов дописывает новые строки (до 800).
- **Утечки слушателей Tauri** (HMR/перезаход): `unlisten` вызывается при
  размонтировании.
- **Broadcast `Lagged`** больше не считается сигналом остановки.
- **CSP** задан (`default-src 'self'`…), `open_url` принимает только
  `tg://` и `https://`.

## [1.1.0] — 2026-10-21

### Исправлено

- **CI снова проверяет ядро**: `core` стал членом workspace, поэтому
  `cargo test/clippy -p tg-ws-proxy-core` находит dev-зависимости (`rcgen`,
  `criterion`); lock-файл перегенерирован, CI собирает с `--locked`.
- **Тестовые DC и DC203**: `ws_domains`/`has_ws_front` нормализуют `10002` и
  `203` к DC2 — WS-маршрут для них больше не пропускается.
- **Счётчик активных соединений** больше не уходит в `u64::MAX` при остановке
  (saturating decrement, без `store(0)` в гонке с дренажом).
- **Атомарное сохранение `config.json`**: временный файл + резервная копия;
  битый конфиг сохраняется как `config.json.broken` вместо тихой перезаписи.
- **Сохранение настроек** не запускает остановленный мост.
- **Keep-alive пула** пингует по одному сокету и ждёт pong (раньше вся очередь
  вынималась на время пинга, а «живость» не проверялась).
- **WS-хендшейк** проверяет `Upgrade: websocket` и `Sec-WebSocket-Accept`.
- **Прогрев пула** больше не открывает мёртвые `kws1/3/5` (у них нет `/apiws`).
- **`pool_size = 0`** действительно отключает пул.
- **Проверка обновлений** сравнивает версии численно: откат на старый тег
  больше не считается обновлением.
- **UI**: максимум буфера приведён к бэкенду (1 МиБ), на дашборде появились
  маршруты DC, ссылки «Помощи» ведут на актуальный репозиторий.
- **Тест связности** больше не показывает DC1/3/5 как ошибки: у них нет
  `/apiws` (302), теперь они помечены «нет WS-фронта», а реально проверяются
  DC2/DC4/DC203 и пользовательские домены.
- **Онбординг** берёт текущий порт и секрет вместо жёсткого `1443`, проверяет
  занятость порта и не закрывается, если сохранение/запуск не удались; в конце
  явно запускает мост.
- **Секрет ядра** больше не печатается в stdout без `--print-secret`.
- **Прогрев пула** заполняет до `min(pool_size, 4)` сокетов на DC2/DC4.
- **Keep-alive пула** настраивается (`pool_keepalive_secs`, `0` — выключить).
- **Android**: foreground service с постоянным уведомлением, чтобы система
  реже выгружала процесс в фоне.
- **CI релизов**: APK подписывается, если заданы Android-секреты; инструкция —
  в `docs/RELEASING.md`.
- **Локальная сборка APK**: `scripts/build-android.ps1` создаёт/переиспользует
  ключ в `%USERPROFILE%\.tgwsproxy\` и собирает подписанный release-APK.
- **Автозапуск открывает только трей**: окно больше не появляется при входе в
  систему (и не мигает), прокси стартует в фоне; окно открывается кликом по
  иконке в трее. Существующая запись автозапуска обновляется с флагом
  `--autostart` автоматически.

### Изменено

- **Сторонние CF-домены** можно отключить (`use_builtin_cf_domains`): тогда не
  используются захардкоженный пул и его обновление с GitHub.
- Убран недокументированный SNI-фолбэк `sprinthost.ru`.
- Обновлены зависимости (Tauri 2.12.5, rustls 0.23.46, tokio 1.54, Vite 8.3.5
  и остальные патчи).

## [1.0.0] — 2026-10-18

Первый стабильный релиз. Ядро перестало быть «набором экспериментов»:
транспорты, пул и обход DPI доведены до предсказуемого поведения, появился
HTTP/3 и подготовка к Android.

### Добавлено

- **HTTP/3 транспорт** (`transport = "h3"`): MTProto идёт телом `POST /mtproto`
  по QUIC с ALPN `h3`. Подходит любой HTTP/3-сервер (nginx, Caddy, Worker) —
  свой протокол на стороне релея больше не нужен.
- **Умный балансировщик**: фоновые пробы доменов (TLS + WS upgrade, DC2 и DC4)
  каждые 5 минут; порядок healthy → неизвестные → мёртвые; живая запись
  успехов/провалов; ротация залипшего домена при полном провале.
- **Recycling буферов**: пул буферов на процесс, переиспользование в обе
  стороны моста и в `send_batch` — на медиа-трафике больше нет аллокации
  `Vec` на каждый WS-фрейм.
- **Реальный keep-alive пула**: WS ping каждые 15 секунд, работает и через TLS;
  мёртвые сокеты выбрасываются, очередь пополняется на попадании.
- **Платформенное определение**: команда `get_platform`; на Android/iOS
  скрываются оконные кнопки, автозапуск и трей.
- **Android**: `minSdkVersion 24`, CI-сборка APK, safe-area отступы, а ссылки
  и логи открываются через `tauri-plugin-opener` (вместо `ShellExecuteW` /
  `xdg-open`) — работает и на мобильных.
- **Тесты**: фрагментация первого пакета без дублирования, порядок
  балансировщика, сквозной HTTP/3 roundtrip, дренаж сессий, валидация конфига,
  uptime/ошибки в статистике.
- **Burn-in тесты жизненного цикла** (`core/tests/burnin.rs`): старт сервера →
  мусорный/неверный/корректный handshake → выживание и учёт в телеметрии →
  shutdown с дренажем и освобождением порта → рестарт на том же порту.
  Плюс: idle-сессия не блокирует остановку, Fake TLS отдаёт 301 на plain HTTP.
- **Валидация конфига**: хост/порт/секрет/буфер/таймаут/релеи/DC-IP проверяются
  до запуска. Раньше опечатка в секрете молча давала нулевой ключ, а порт `0`
  приводил к случайному порту — теперь внятная ошибка.
- **Uptime и диагностика в UI**: время работы моста, счётчик сбоев и текст
  последней ошибки прямо на дашборде, с копированием для issue.
- **Корректная остановка**: активные сессии больше не обрываются на полпути —
  им даётся окно на сброс буферов и WebSocket close, после чего сессии
  принудительно снимаются (дренаж никогда не зависает).

### Исправлено

- **Паника в ядре без установленного rustls-провайдера**: дерево зависимостей
  содержит и `ring`, и `aws-lc-rs`, поэтому rustls паникует с
  «Could not automatically determine the process-level CryptoProvider», если
  никто не вызвал `install_default`. GUI-бинарь ставил его в `main`, но встроенное
  ядро (тесты, сторонние инструменты) — нет; фоновые TLS-пробы балансировщика
  упирались в это сразу. Провайдер теперь ставится в `run_server_with_stats`.
- **Мёртвые кнопки в UI**: `toggleProxy`, `restartProxy`, `saveSettings`,
  `generateSecret`, `applyPreset`, `toggleAutostart`, `checkForUpdates`,
  `runConnectivityTest` не были в возврате `useProxy()` — клики по «Старт»,
  «Рестарт», «Сохранить», пресетам и тесту связи молча падали с
  «is not a function». Действия добавлены в возврат, импорты выпрямлены.
- Сплиттер отправлял первый пакет дважды (`extend` вместо замены) — ломало
  любую сессию.
- **Windows: порт-хайджек.** `SO_REUSEADDR` позволял второму процессу встать
  на уже слушающий порт: два прокси делили трафик, диагностика «порт занят»
  не срабатывала. Теперь reuse только на Unix.
- Тумблер автозапуска не включался (двойная обработка `v-model` + `@update`).
- `socket2 0.6` / `rand 0.10`: обновлён код под новый API.

### Изменено

- Минимальная версия Rust — 1.85 (edition 2024), зависимости на latest:
  `socket2 0.6`, `rand 0.10`, `criterion 0.8`, `rcgen 0.14`, `h3 0.0.8`.
- `cfproxy_h2_media` больше не влияет на поведение: H2-пул удалён как мёртвый
  код, его место занимает HTTP/3.

### Ограничения

- Прозрачное переключение апстрима посреди сессии невозможно: ключи MTProto
  привязаны к соединению. Failover работает на этапе установки, при обрыве
  клиент переподключается сам.
- Android: прокси живёт, пока процесс приложения в памяти. Foreground Service
  (чтобы мост не убивался в фоне) появится отдельным релизом.
- TCP Fast Open не включён: в `socket2 0.6` нет API, нужны платформенные
  сисколлы, а выигрыш перекрывается TLS-handshake.
